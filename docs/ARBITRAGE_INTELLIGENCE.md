# Arbitrage Intelligence (research-only foundation)

The arbitrage package is isolated from the existing spot tournament. Seven strategy modules implement the common `TradingStrategy` interface and consume normalized snapshots. The strategy scanner persists the input funding rates, top-of-book quotes, basis and candidate/rejection records. It has no exchange order API, signing key, or live execution path.

## Install and inspect

```sh
php deploy/arbitrage.php schema
php deploy/arbitrage.php market-snapshot BTCUSDT
php deploy/arbitrage.php scan storage/research/your_snapshot.json
php deploy/arbitrage.php init-portfolios research_default 10000
php deploy/arbitrage.php reconcile-portfolios research_default
php research/arbitrage/strategy_tests.php
php research/arbitrage/ledger_integration_check.php
php deploy/arbitrage.php backtest DATASET.json FUNDING_RATE
php deploy/arbitrage.php backtest XEMM_DATASET.json CROSS_EXCHANGE_MM
```

The public funding collector supports Binance USD-M, Bybit linear, OKX USDT swap, Bitget USDT futures, and Hyperliquid. The orderbook collector supports spot/perpetual depth for Binance, Bybit, OKX, Bitget, and Hyperliquid perpetual. The dated-futures collector currently uses Bybit linear delivery instrument metadata and order books; it filters trading `LinearFutures` contracts with future `deliveryTime` from Bybit's [instrument-info endpoint](https://bybit-exchange.github.io/docs/v5/market/instrument) and [orderbook endpoint](https://bybit-exchange.github.io/docs/v5/market/orderbook). `DexPoolCollector` can observe up to eight operator-selected pools per run using GeckoTerminal's public [pool API](https://api.geckoterminal.com/docs/index.html); `EvmGasCollector` reads `eth_gasPrice` from HTTPS JSON-RPC endpoints supplied by the operator. Configure `PROMETHEUS_DEX_POOLS` as a JSON array of objects with `network`, `pool_address`, optional `label`, and an explicit `amm_model` of `CONSTANT_PRODUCT` for each pool eligible for route simulation; configure `PROMETHEUS_EVM_RPC_ENDPOINTS` as a JSON object mapping chain names to HTTPS endpoint URLs. Configure `PROMETHEUS_DEX_ROUTES` as a JSON array with `network`, `buy_pool_address`, `sell_pool_address`, `input_quote_amount`, explicit decimal `buy_fee_rate`/`sell_fee_rate`, `gas_units`, and `native_token_price_usd`. For hybrid routes, configure `PROMETHEUS_DEX_CEX_ROUTES` with `network`, `pool_address`, `direction`, `symbol`, `cex_venue`, `quote_token_price_usd`, `dex_fee_rate`, `cex_fee_rate`, `cex_slippage_bps`, `adverse_selection_cost_usd`, `gas_units`, and `native_token_price_usd`; provide either `quote_input_amount` for `BUY_DEX_SELL_CEX` or `base_quantity` for `BUY_CEX_SELL_DEX`. Optional route guards include a maximum pool skew/age and quote-price tolerance. Keep provider URLs in environment configuration. The public GeckoTerminal API is beta, cached for up to one minute and limited to approximately ten requests per minute; the collector caps each invocation at eight pool requests. DEX/DEX and DEX/CEX simulators model only explicitly declared constant-product pools. The former applies the exact-input `x*y=k` curve to each same-chain leg; the latter combines one pool curve with CEX orderbook depth, fees and configured slippage. Both price gas from observed wei price, configured gas units and native-token USD price. Concentrated-liquidity and dynamic-fee pools are rejected because whole-pool balances do not describe their active liquidity. Output is observation/backtest research only; it does not establish transaction inclusion or settlement, calibrate reverts, or submit swaps/orders. Revert probability stays uncalibrated and a full configured gas amount is reserved as revert cost. XemmQuotePlanner emits passive paper quote intents from explicit fees, slippage and adverse-selection costs; XemmEventReplay consumes the intents and only fills from timestamped historical maker-fill records. Run `php deploy/arbitrage.php market-snapshot BTCUSDT` to collect rates, books and dated basis into a normalized snapshot; configured DEX and gas feeds are added as observations and histories. `PROMETHEUS_ARBITRAGE=1` includes funding collection in `cron.php`. A missing venue response is recorded as a connector error and is not replaced with a value. Historical records accumulate from collection start; the collector does not claim a historical backfill. Bybit/OKX intervals come from exchange data; Binance interval is derived from consecutive settlement times (8 hours only when the API returns fewer than two records); Hyperliquid funding is hourly.

`market-snapshot` includes funding, depth, Bybit dated-futures basis, and configured DEX/gas observations. Complete DEX/DEX and DEX/CEX configs are simulated by the MEV observation strategy using matching pools, CEX books and fresh gas observations; absent, stale, or unsupported inputs do not produce a candidate. The DEX feed stores token prices, reported token balances, reserve USD and 24-hour volume from the provider. The EVM feed stores gas price in wei; route gas USD is calculated only when gas units and native-token USD price are supplied. The dated-basis feed provides book/expiry evidence only, so it is flagged cost-incomplete and the risk gate rejects it until costs are supplied. It never fabricates those data. Other research snapshots use the same format; see the example file. `snapshot_at` is UTC. Rates are decimal fractions, e.g. `0.0001` means 0.01%; funding intervals are explicit hours. Funding expected income is horizon-based and stays labeled estimated until a funding settlement is simulated. Contract annualization is limited to dated futures. Funding reversal probability uses non-overlapping 24-hour sign-flip labels with chronological fit, validation and test blocks. It is emitted only with at least 30 fit labels and 10 labels in each holdout, and only when both validation and test frequency errors stay within the configured tolerance; otherwise the estimate remains null. Statistical pair analysis includes an exploratory maximum standardized mean-shift scan; its threshold is not multiple-testing corrected. Funding risk rejects a mix of settled and forecast rates. XEMM fill probability is estimated from time-separated, feature-matched history and is called calibrated only after a minimum sample and holdout-error check. Other success probabilities remain null without calibration. Framework evaluation and integration decision are documented in `ARBITRAGE_INTEGRATION_REVIEW.md`.

Triangular research snapshots may provide `triangular_edges` with venue, source/destination asset, executable conversion rate, fee rate, input-asset depth, minimum input quantity, and quantity step. The scanner finds directed three-edge cycles within one venue, applies size rounding and depth checks, and emits a simulation candidate; this is not a sequential fill guarantee.

The scanner rejects observations older than 30 seconds by default and records candidate failures with reasons. Risk gates enforce a 5% per-opportunity cap, 25% exchange exposure, gross exposure below virtual equity, 10% drawdown kill switch, duplicate-signal rejection and a three-error circuit breaker. Funding history is summarized over 7/30/90 days from records actually ingested; reversal estimates show sample and validation status and remain null without adequate evidence. Ranking min-max normalizes return on capital, validated probability, observed liquidity, funding persistence, comparable out-of-sample Sharpe and data quality; missing evidence is omitted and unvalidated probabilities are excluded. Experimental weights are recorded with every candidate. Regime detection currently uses a trend and EWMA-style volatility heuristic, and labels confidence uncalibrated. The UI separates paper/backtest classifications, displays the funding reversal estimate with sample size and validation status, and does not present a projection as realized profit.

`MarginStressEngine` calculates isolated-margin liquidation prices and portfolio cross-margin stress when positions, shared collateral by venue, maintenance/liquidation rates and market-return scenarios are supplied. `RiskManagementEngine::evaluate` rejects opportunities that breach either explicit stress model. It does not infer exchange margin tiers or supply default shocks; the backtester itself remains single-position, unlevered by default, and uses isolated liquidation only when a venue margin profile is explicitly provided.

`EventDrivenBacktester` accepts ordered events with `as_of_utc`, `available_at_utc` and snapshots containing books. Signals are read from each snapshot's `signal` field, and the replay executes only the final chronological test partition. Open and close fills occur at a later eligible event, use book depth, fees and slippage, and preserve partial fills. Optional `exchange_status` records can simulate venue outages; optional `funding_settlements` records are booked only after their settlement and availability times. Perpetual positions reserve full notional (no leverage). If config provides `margin_profiles[venue]` with exchange maintenance and liquidation-fee rates, the replay checks each perp mark and force-closes a breached position against current book depth, books a liquidation fee, and activates the kill switch. Without a profile, liquidation is disabled and reported in result limitations. `runWalkForwardModel` separates fit, validation and test callbacks, records the time windows and data hashes, and only calls the predictor during test; the CLI scan remains a historical-signal replay and does not fit models on its own. The replay is still single-position and does not model a two-venue perp hedge or cross-margin account state. Deterministic circular block bootstrap reports final-equity and drawdown percentiles for closed-trade returns. Daily out-of-sample equity is persisted by backtest for cross-strategy comparisons. Risk-parity recommendations require at least 20 synchronized test-return dates and identical test start/end timestamps across multiple strategies; no in-sample return series is accepted. Train and validation partitions are excluded from trading; the CLI's recorded-signal replay does not fit models or generate signals, while callers can use the walk-forward callback API.

For `CROSS_EXCHANGE_MM`, the backtest routes to `XemmEventReplay`: test snapshots can provide timestamped post/cancel decisions or `xemm_quote_config`, confirmed `maker_fills`, and hedge venue depth. `XemmQuotePlanner` computes passive prices and depth-limited hedge economics from explicit costs; the replay applies activation/cancel latency, stale quote cancellation, partial hedge retries, fees and slippage. The replay treats historical maker-fill events as observed input; it does not estimate queue position or transmit orders.

`PortfolioLedger` supports idempotent paper position opening after a confirmed simulated hedge, atomic delta-neutral multi-leg group opening and full-group closing, mark-to-market, settled funding entries, single-position partial/full close, trade metrics and equity reconciliation. Group operations share one database transaction; a failed leg rolls the whole operation back, and group close requires every leg to close fully. `reconcile-portfolios KEY` audits without writes; adding `--repair` updates derived virtual equity from cash and open positions. These methods have no exchange credentials or order-transmission path.

## Data and execution limits

The funding collector provides public current/settled rates; the book collector supplies top-of-book plus depth; the dated-futures collector provides Bybit delivery books and basis. The simulator can replay funding and cash-and-carry opening legs, XEMM quote/cancel and delayed hedge events from historical records, and single-venue spot or unlevered perp backtests. Funding settlement rows must be historically timestamped and available in the event stream; the backtester does not synthesize them. The paper ledger atomically opens and fully closes paired positions, but does not persist exchange acknowledgements or recover external venue inventory because it never sends live orders. The risk engine supports explicit isolated and cross-margin stress scenarios; the event replay remains single-position and does not manage a cross-margin account. Statistical analysis now selects ADF lag length by AIC or BIC (BIC by default), reports a MacKinnon asymptotic p-value and a finite-sample Engle-Granger critical-value response surface for the two-series/no-trend case. The p-value remains asymptotic; the critical response is an approximation when lag augmentation is selected. MEV is observation/backtest only, including constant-product DEX/CEX book-depth simulation without transaction inclusion or settlement modeling. Hummingbot, CCXT and NautilusTrader were reviewed as references; none is installed because the existing PHP 7.4/HostGator deployment does not have the asynchronous Rust/Python execution architecture needed to adopt them safely.

- Hummingbot uses Apache-2.0 and has reusable exchange connectors and market-making/arbitrage references: https://github.com/hummingbot/hummingbot
- CCXT uses MIT and provides a unified PHP API, but current releases require PHP 8.1 and additional Composer dependencies; the PROMETHEUS deployment targets PHP 7.4, so it was not added: https://github.com/ccxt/ccxt
- NautilusTrader uses LGPL-3.0 and is a Rust-native event-driven engine. It would be a separate service and a significant deployment change, so it remains a research reference: https://github.com/nautechsystems/nautilus_trader
- Engle–Granger finite-sample critical values and approximate p-value response surfaces follow [MacKinnon (2010)](https://ageconsearch.umn.edu/record/273723/files/qed_wp_1227.pdf) and [MacKinnon (1994)](https://qed.econ.queensu.ca/working_papers/papers/qed_wp_861.pdf); the published MacKinnon polynomial coefficients are also documented in the [Statsmodels ADF implementation](https://github.com/statsmodels/statsmodels/blob/main/statsmodels/tsa/adfvalues.py).

## Remaining research boundaries

The remaining boundaries are deliberate or data-dependent: no live order transmission or external venue inventory recovery is implemented, because the system is paper/observation-only; the persistent virtual ledger does reconcile after process restarts. Cross-margin portfolio stress is available to the risk engine, while the event replay remains single-position. XEMM fill probability is emitted as calibrated only when chronological train/validation data meet sample and error thresholds; otherwise it is unavailable or unvalidated. DEX simulation is limited to declared constant-product pools and does not model transaction inclusion, reverts or settlement. The Engle-Granger p-value is an asymptotic MacKinnon approximation; finite-sample critical values use an approximate response surface. Regime classification remains an EWMA/trend heuristic without calibrated HMM transitions. CLI backtests replay recorded signals; model fitting is available through `runWalkForwardModel` callbacks, and bootstrap ranges remain conditional on observed test trades. These are research and paper tools, not evidence of profitability or production execution.
