# Review de integração de frameworks de arbitragem

**Data da revisão:** 27 de novembro de 2026. A decisão abaixo é para o PROMETEU atual, cuja plataforma de pesquisa é PHP com um pequeno conjunto de ferramentas Python. Nenhum framework foi instalado.

| Projeto | O que oferece | Licença observada | Adequação ao PROMETEU |
| --- | --- | --- | --- |
| [Hummingbot](https://github.com/hummingbot/hummingbot) | Cliente Python de negociação, conectores que mantêm order books e estado de ordens; a arquitetura [Strategy V2](https://hummingbot.org/strategies/v2-strategies/) usa scripts, controllers e executors; ver também [arquitetura dos conectores](https://hummingbot.org/connectors/connectors/architecture/). | Apache-2.0 ([LICENSE](https://github.com/hummingbot/hummingbot/blob/master/LICENSE)) | Boa referência para ciclo de vida de conectores, ordens em voo, latência e hedge. Adotar o runtime completo criaria um segundo motor Python com estado e execução próprios, desnecessários no modo de pesquisa atual. Reutilizar padrões, sem dependência de runtime.
| [CCXT](https://github.com/ccxt/ccxt) | API unificada para mercados e métodos REST de exchanges em PHP, Python e outras linguagens; ver o [manual da API unificada](https://github.com/ccxt/ccxt/wiki/Manual). | MIT ([repositório](https://github.com/ccxt/ccxt)) | É a opção mais compatível com a camada PHP existente se a manutenção de muitos conectores REST se tornar custosa. Os coletores atuais já isolam normalização e usam endpoints públicos diretamente; acrescentar CCXT agora duplicaria esse trabalho e ampliaria dependências. Reavaliar antes de expandir a matriz de exchanges. A cobertura WebSocket e os termos da edição CCXT Pro precisam de revisão separada se forem requisitos.
| [NautilusTrader](https://github.com/nautechsystems/nautilus_trader) | Motor determinístico orientado a eventos, núcleo Rust com APIs Python e [adaptadores](https://github.com/nautechsystems/nautilus_trader/blob/develop/docs/concepts/adapters.md) de dados/execução. A documentação descreve adaptadores customizados como pacotes separados. | LGPL-3.0-only ([manifesto do workspace](https://github.com/nautechsystems/nautilus_trader/blob/develop/Cargo.toml)) | Mais próximo de um motor completo de execução e backtest que de uma biblioteca de normalização. A integração exigiria runtime Python/Rust, tradução de tipos e revisão das obrigações LGPL na forma de distribuição. É excessivo para a camada PHP de observação atual; considerar como processo isolado caso o PROMETEU passe a exigir replay/eventos de baixa latência em produção.

## Decisão

Não adicionar dependências neste ciclo. Manter os coletores isolados por interface e a camada de pesquisa/paper trading existente. Se houver adoção futura, manter fronteira de processo explícita: snapshot normalizado e versionado na entrada; sinais, eventos de execução simulada e métricas versionados na saída; sem credenciais de saque, transmissão real ou autoridade de risco no adaptador externo. Qualquer adaptador deverá ter testes de contrato para símbolos, intervalos de funding, profundidade, precisão e timestamps.

O Hummingbot permanece referência de engenharia de conectores, CCXT é candidato a normalização REST em PHP e NautilusTrader é candidato a runtime separado de replay/eventos. Essa decisão não valida compatibilidade de uma versão instalada: não há dependência instalada nem versão fixada no `composer.lock`/ambiente Python do PROMETEU.
